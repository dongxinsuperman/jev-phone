# Upgrades and maintenance

Current version: **0.1.1 (2026-10-13)**. Install from source or a wheel.

The commands below target macOS / Linux and use Python 3.11 as an example. Before upgrading, enter the repository directory; reuse an existing virtual environment or create one with `python3.11 -m venv .venv`.

## Install or upgrade

An authorized GitHub account with Git authentication is required to clone the repository. For a first source install, run `git clone https://github.com/dongxinsuperman/jev-phone.git` and `cd jev-phone` before the commands below; this is not needed for an unpacked delivery archive. Save local changes before switching versions. Stop active SDK calls and your Demo process first.

```sh
git fetch origin --tags
git checkout v0.1.1
.venv/bin/python -m pip install -e '.[android]'
.venv/bin/python -c "from importlib.metadata import version; print(version('jev-phone'))"
```

Use `-e .` for iOS, `-e '.[harmony]'` for HarmonyOS, or `-e '.[demo]'` for the Demo. Python 3.10+ and Pillow 10.1+ are required. Restart the consuming Python process after installation. An editable install uses the checked-out source; a wheel install uses the installed distribution.

Alternatively, install the wheel supplied in the delivery archive:

```sh
.venv/bin/python -m pip install './wheel/jev_phone-0.1.1-py3-none-any.whl[android]'
```

Do not use `pip install --upgrade jev-phone` to obtain this project: it has not been published to PyPI. Use the corresponding version tag or wheel.

## Compatibility and rollback

0.1.1 is compatible with the Clicker constructors, `click`, `run`, events and results in 0.1.0. See [CHANGELOG](../CHANGELOG.md) for version changes.

For source rollback, check out `v0.1.0` and reinstall the required extras. For wheel rollback, reinstall the saved previous wheel. Restart the consuming process afterward.

## Reporting issues

Use repository Issues to report the SDK version, platform, reproduction steps and sanitized error logs.

## Source archives, wheels and documentation

The wheel contains the SDK and Demo resources, but not repository examples or documentation. The full delivery archive includes them. For an existing checkout, `git fetch origin` followed by `git pull --ff-only` on your main branch updates documentation; `v0.1.1` keeps the SDK source pinned to its delivered revision. The archive manifest records its source commit and file SHA-256 hashes for verification.
