# Upgrades and maintenance

Current version: **0.2.0 (2026-10-15)**. Install from source or a wheel.

The commands below target macOS / Linux and use Python 3.11 as an example. Before upgrading, enter the repository directory; reuse an existing virtual environment or create one with `python3.11 -m venv .venv`.

## Install or upgrade

The public repository can be cloned without signing in to GitHub. For a first source install, run `git clone https://github.com/dongxinsuperman/jev-phone.git` and `cd jev-phone` before the commands below; this is not needed for an unpacked delivery archive. Save local changes before switching versions. Stop active SDK calls and your Demo process first.

```sh
git fetch origin --tags
git checkout v0.2.0
.venv/bin/python -m pip install -e '.[android]'
.venv/bin/python -c "from importlib.metadata import version; print(version('jev-phone'))"
```

Use `-e .` for iOS, `-e '.[harmony]'` for HarmonyOS, or `-e '.[demo]'` for the Demo. Python 3.10+ and Pillow 10.1+ are required. Restart the consuming Python process after installation. An editable install uses the checked-out source; a wheel install uses the installed distribution.

Alternatively, download the wheel from PyPI and install it:

```sh
.venv/bin/python -m pip download --no-deps 'jev-phone==0.2.0' --dest wheel
.venv/bin/python -m pip install './wheel/jev_phone-0.2.0-py3-none-any.whl[android]'
```

Version 0.2.0 is available on [PyPI](https://pypi.org/project/jev-phone/0.2.0/). Install or update with `python -m pip install --upgrade "jev-phone[android]==0.2.0"`; replace the extra for your platform. Restart the consuming process after an upgrade.

## Compatibility and rollback

0.2.0 preserves existing 0.1.1 / 0.1.0 call patterns. The new process-wide `configure(visual_enhancement=True)` switch is off by default. It enables available H5 and native drawing refinements on every platform without changing tap centers. Native iOS clipping needs the bundled read-only WDA extension; iOS H5 inspection needs `jev-phone[visual]`. Unsupported or unreliable channels keep the original drawing. See [CHANGELOG](../CHANGELOG.md) for version changes.

For source rollback, check out `v0.1.1` and reinstall the required extras. For wheel rollback, reinstall the saved previous wheel. Restart the consuming process afterward.

## Reporting issues

Use repository Issues to report the SDK version, platform, reproduction steps and sanitized error logs.

## Source archives, wheels and documentation

The wheel contains the SDK and Demo resources, but not repository examples or documentation. The full delivery archive includes them. For an existing checkout, `git fetch origin` followed by `git pull --ff-only` on your main branch updates documentation; `v0.2.0` keeps the SDK source pinned to its delivered revision. If a full delivery archive includes a manifest, it records source and file hashes. GitHub source archives and PyPI distributions do not necessarily include that delivery manifest.
