# Upgrades and maintenance

Current delivery: **0.1.1 (2026-10-13)**. The GitHub repository remains private. This delivery includes source and a wheel; nothing is published to PyPI.

The commands below target macOS / Linux and use Python 3.11 as an example. Before upgrading, enter the repository directory; reuse an existing virtual environment or create one with `python3.11 -m venv .venv`.

## Install or upgrade

An authorized GitHub account with Git authentication is required to clone the repository. For a first source install, run `git clone https://github.com/dongxinsuperman/jev-phone.git` and `cd jev-phone` before the commands below; this is not needed for an unpacked delivery archive. Save local changes before switching versions. Stop active SDK calls and your Demo process first.

```sh
git fetch origin --tags
git checkout v0.1.1
.venv/bin/python -m pip install -e '.[android]'
.venv/bin/python -c "from importlib.metadata import version; print(version('jev-phone'))"
```

Use `-e .` for iOS, `-e '.[harmony]'` for HarmonyOS, or `-e '.[demo]'` for the Demo. Python 3.10+ and Pillow 10.1+ are required. Restart the consuming Python process after installation. An editable install uses the checked-out source; a wheel install uses the installed distribution.

Alternatively, install the wheel supplied in the delivery archive:

```sh
.venv/bin/python -m pip install './wheel/jev_phone-0.1.1-py3-none-any.whl[android]'
```

Do not use `pip install --upgrade jev-phone` to obtain this project: it has not been published to PyPI. Use an explicit private Git tag or a supplied wheel.

## Compatibility and rollback

0.1.1 retains the existing Clicker constructors, `click`, `run`, events and results. The existing drawing implementation, execution flow and V3 stability parameters are preserved. See [CHANGELOG](../CHANGELOG.md) for the delivered changes.

For source rollback, check out `v0.1.0` and reinstall the required extras. For wheel rollback, reinstall the saved previous wheel. Restart the consuming process afterward.

## Maintenance

Keep the version in pyproject.toml, CHANGELOG and upgrade instructions synchronized. Use patch versions for fixes, minor versions for compatible additions, and document migrations for incompatible interfaces. Run unit tests on each delivery; the SDK checks workflow runs tests on GitHub and does not publish packages. Platform changes require relevant device regression separately.

Build and verify a wheel in an isolated environment, generate SHA-256 manifests, and tag the exact source commit for each delivery. Report issues privately with the version, platform and sanitized evidence; never include model keys or personal device logs. Demo and external users continue to share the same SDK. There is no automatic updater or PyPI publishing pipeline.

The wheel contains the SDK and Demo resources, but not repository examples or documentation. The full delivery archive includes them. For an existing checkout, `git fetch origin` followed by `git pull --ff-only` on your main branch updates documentation; `v0.1.1` keeps the SDK source pinned to its delivered revision. Documentation corrections after the tag do not change SDK behavior or move the tag.
