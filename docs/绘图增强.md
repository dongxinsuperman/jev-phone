# 三端可选绘图增强（源码版本）

只设置一个总开关，默认关闭。配置对当前 Python 进程内所有 SDK 实例生效，包括已经创建的实例；在应用启动时配置即可。关闭后，下一次采集不读取增强通道，使用原绘图。

```python
from jev_phone import configure

configure(visual_enhancement=True)   # 三端启用各自已经验证的增强
# configure(visual_enhancement=False)  # 三端全部关闭
```

AndroidClicker、IOSClicker、HarmonyClicker 的常规调用方式保持原样，不分别传平台开关，也不再传 visual_dom / visual_native。

| 平台 | 总开关开启后的行为 |
| --- | --- |
| Android | H5 DOM 增强 + 原生 View 绘制主体增强 |
| iOS | H5 WebKit 增强 + 同快照 UID / visibleFrame 原生可见区域修正 |
| HarmonyOS | H5 ArkWeb 增强 + uniqueId / RenderService 原生背景与圆角 |

“全部开启”指各端已经验证且当前设备提供可靠信息的路线。原生与 H5 的可用性分别判断，一条不可用不影响另一条。没有调试通道、上下文不唯一、原生遮罩令 WebView 不可见、映射不支持或读取失败时，保留原框。增强仅改变展示区域，候选编号、真实点击区域、点击点、步骤执行和 V3 页面稳定等待参数保持原样。

## 安装与设备绑定

这项功能尚未发布，请从当前源码安装。按使用的平台选择依赖：

```bash
python -m pip install -e '.[android]'          # Android
python -m pip install -e '.[visual]'           # iOS 增强工具
python -m pip install -e '.[harmony]'          # HarmonyOS
```

iOS 使用已验证的 pymobiledevice3 11.29.0 协议实现，组件拥有自己的持续连接，并在读取后释放页面会话；没有缓存画面或 DOM。现有 WDA、签名和真机准备方式不变。设备需开放 Web Inspector，应用的 WKWebView 需可检查。仅验证了全屏 WebView 映射；嵌入或存在多个可见上下文时不猜测。

本地 WDA 且只有一台 USB 设备时自动绑定；多设备或远程 WDA 时明确传入与 WDA 对应的 USB UDID：

```python
from jev_phone import IOSClicker

clicker = IOSClicker(wda_url, api_key, session_id=session_id, udid=device_udid)
```

UDID 是设备定位信息，不是另一项增强开关。组件关闭时只释放自己创建的检查连接，不停止共享 WDA。

HarmonyOS 开启增强时，使用 UiTest 的 `dumpLayout -e uniqueId` 替代当次 captureLayout，取得同一份树的边界、origBounds 与系统身份；成功时不再调用 captureLayout。原生候选通过 exact uniqueId → FrameNodeId → RenderService 关联背景与圆角，不依赖业务文字、应用资源 ID 或模糊距离匹配。没有原生候选时不读取 RenderService。若设备不支持该树通道或读取失败，当次使用原 captureLayout；该适配器随后不反复探测，重新创建适配器可重新尝试。关闭总开关时始终使用原 captureLayout。通过前台应用动态找到 ArkWeb 调试通道，临时转发使用独立端口，结束后只清理自己创建的转发。Android / 鸿蒙本机仍需 adb / hdc。

## iOS 原生通道：可选 WDA 扩展

iOS 原生可见区域需要随 SDK 提供的只读 WDA 扩展，原版 WDA 没有这个端点。对自己的 WDA 源码先检查，再应用补丁，并按原有方式构建、签名和启动：

```bash
python -m jev_phone.wda_patch /path/to/WebDriverAgent --check
python -m jev_phone.wda_patch /path/to/WebDriverAgent
```

补丁只增加 `GET /session/:sessionId/wda/nativeGeometryProbe`。它从一份新快照取得普通控件字段、UID 与 visibleFrame，不触发点击，不修改等待参数，不缓存画面。首次解析应用进程的根 AX 引用有初始化成本；之后仅复用根引用，每次仍读取新快照。SDK 用这份快照替代当次普通 XML 取树，不在原取树之后追加第二次完整快照。补丁不匹配时不会修改文件，需要使用匹配的 WDA 源码版本；SDK 本身不会编译、安装、重签或替换用户 WDA。

原版 WDA 返回 404/405 时，当次继续普通取树，该适配器后续不再请求缺失端点；H5 仍可独立增强。安装扩展后重新创建适配器即可重新识别。缺失、重复 UID、截断或无效快照都不用于增强。小数坐标取整差异不会算成收益；区域裁切后若不包含原点击中心，也不会使用。

鸿蒙的共享父级背景只在系统身份明确、背景不透明且边缘关系成立时提供部分圆角。检测到动画、旋转、缩放、透明祖先，或者无法验证的非均匀圆角和复杂 Canvas 轮廓时保留原框，不推测完整形状。绘制编号与引线仍留在增强框内；标注放不下时，沿用现有整图绘制回退。

## 耗时与回退

没有新增业务等待、轮询页面稳定、自动重试点击或结束截图。I/O 截止时间用于终止不可用通道，不是额外等待。

iOS 新建检查连接有设备端间隔限制，初始化可能需要数秒；正常调用复用协议连接。SDK 的增强计时包括当前应用信息读取等接入成本，不能直接拿探索工具仅测通道的时间代替 SDK 时间。请以实际返回的 timings.visual_enhancement 为准。

结果中的 visual_enhancement 分别记录 dom / native 的状态、数量和时间；原生状态 `matched` 表示获得可靠绘图区域，`no_reliable_geometry` 表示没有需要修正的区域，`not_applicable` 表示没有可用原生候选，`unavailable` 表示通道不支持或读取失败。这些状态不影响原有点击能力。原生 `capture_ms` 表示替代取树的耗时，`elapsed_ms` 表示后续几何关联耗时；两者都已计入对应 `timings.tree` / `timings.visual_enhancement`，不要再与整步总计重复相加。匹配数量不等于准确率。visual_render_fallback 表示绘图异常时整图回退。

本节介绍源码版本中的增强接口；包版本字段仍为 0.1.1。已发布的 PyPI 0.1.1 不包含此配置入口，使用增强功能请安装包含本次改动的源码。

## 本地验证入口

准备好目标页面后，可以只采集、不点击地对比 SDK 开关前后：

```bash
PYTHONPATH=. python experiments/annotation_lab/verify_native.py ios \
  --wda-url http://127.0.0.1:8100 --session-id YOUR_SESSION --output /tmp/jev-ios
PYTHONPATH=. python experiments/annotation_lab/verify_native.py harmony \
  --serial YOUR_HDC_SERIAL --output /tmp/jev-harmony
python -m unittest discover -s tests -q
```

对比脚本使用真实适配器和核心绘图；输出同一截图的 before / after、开关前后的候选契约检查和分段时间，不调用模型、不执行点击。设备解锁、应用页面准备与 WDA 构建均由调用方在采集前完成。输出树可能包含页面私有信息，请保存在本地，不直接上传。
