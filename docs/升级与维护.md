# SDK 升级与维护

当前交付版本：**0.1.1（2026-10-13）**。源码保存在私有 GitHub 仓库；本次提供源码交付包和 wheel，不发布 PyPI。Demo 与外部调用方使用同一 SDK。

## 获取与安装

仓库访问需要 GitHub 账号获得权限。已授权用户可克隆仓库并固定版本：

```sh
git clone https://github.com/dongxinsuperman/jev-phone.git
cd jev-phone
git checkout v0.1.1
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[android]'
```

iOS 使用 `-e .`，鸿蒙使用 `-e '.[harmony]'`；Demo 使用 `-e '.[demo]'`。Python 要求 3.10+，Pillow 要求 10.1+。设备服务与模型 Key 由调用方自行配置。

交付包解压后，也可以安装包内 wheel，无需克隆仓库：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install './wheel/jev_phone-0.1.1-py3-none-any.whl[android]'
```

## 从旧版升级

结束当前调用并停止自己启动的 Demo 进程，再更新代码和依赖。先用 `git status --short` 确认本地改动已提交或保存；不要覆盖自己的代码。

```sh
git fetch origin --tags
git checkout v0.1.1
.venv/bin/python -m pip install -e '.[android]'
.venv/bin/python -c "from importlib.metadata import version; print(version('jev-phone'))"
```

升级 wheel 安装时，重新执行对应版本的 wheel 安装命令即可。安装完成后重启使用 SDK 的 Python 程序或 Demo，让进程加载新代码。已经运行的进程不会自动更新。编辑安装直接使用当前 checkout 的源码；wheel 安装使用环境中安装的版本。

**不要通过 `pip install --upgrade jev-phone` 获取本项目更新**：本项目尚未发布 PyPI。每次更新使用明确的私有仓库 tag 或交付 wheel，避免误装同名包。

## 兼容与回退

0.1.1 保留 Clicker 构造参数、`click`、`run`、事件和结果接口；本次不改变绘图现状、步骤拆分、执行顺序或 V3 等待参数。变更清单见 [CHANGELOG](../CHANGELOG.md)。

需要回退时，对源码安装执行 `git checkout v0.1.0` 后重新安装对应 extras；wheel 安装重新安装保存的旧版 wheel。随后重启调用程序。交付时保留上一版包，便于回退。

## 后续维护方式

- 版本记录在 `pyproject.toml`，每次交付同步更新 CHANGELOG 和安装说明。
- 缺陷修复提升补丁版本；兼容的新能力提升次版本；不兼容的接口变更必须明确写出迁移方法。
- 每次提交运行单元测试；GitHub 的 SDK checks 自动验证提交。设备回归按变更涉及的平台安排，不把单元测试当成真机验证。
- 交付前构建 wheel、检查隔离安装和版本读回，生成带 SHA-256 清单的源码包；私有 Git tag 标记对应代码。
- 问题通过私有仓库 Issues 记录：版本、平台、异常、脱敏后的步骤和日志。不要上传模型 Key、个人账号或完整设备日志。
- 保持独立组件边界：Demo 调用同一 SDK，不引入 AI Phone 框架；通道与 V3 参数调整必须有明确来源与变更记录。

本次交付没有自动更新器、PyPI 上传或公开发布流程。GitHub 测试 Workflow 只安装依赖并运行测试，不上传 SDK。
