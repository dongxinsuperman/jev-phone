# 独立组件：位置、入口与接入

从交付包解压后的项目根目录开始。可分发的 Python 组件是 `jev_phone/`，不是网页、`.context/` 或 AI Phone 仓库。对外入口是 `jev_phone/__init__.py`；单步执行核心在 `jev_phone/core.py`，平台实现分别在 `jev_phone/adapters/android.py`、`ios.py`、`harmony.py`，模型协议在 `decisions.py`。

`jev_phone_demo/` 是独立的网页消费者。组件没有独立常驻服务启动命令：外部 Python 程序创建 Clicker 实例并调用 `.click(target)` 即运行。网页启动命令 `jev-phone-demo` 只用于体验 Demo。

## 一段内容直接执行

```python
from jev_phone import AndroidClicker, RunFailure

with AndroidClicker(serial, api_key) as phone:
    try:
        report = phone.run("点击显示与亮度；点击护眼模式")
        print(report["results"], report["transitions"])
    except RunFailure as error:
        print(error.report)  # 已完成步骤、失败步骤和错误；后续未执行
```

`run(text, on_event=None)` 使用与 Demo 相同的符号拆分规则（最多20步），在同设备锁内顺序执行。每步模型只接收当前目标。第一步直接观察，步骤之间复用V3图片对比：最长边480、像素差阈值12、变化比例0.001、4秒对比预算；安卓采样间隔100ms，鸿蒙无额外采样等待，iOS200ms。最后一步不添加对比等待。对比到预算上限未确认稳定时沿用V3返回末帧继续；点击／定位失败停止，RunFailure.report保留已完成结果。同步截图的在途请求由设备传输层超时控制，对比预算在请求返回时检查。

三端复用对比返回的最后一帧，不重复截图。iOS使用当前V3 WDA按需截图方案（不推流），取一次树并用Application几何转换pixel/point，不额外查询视口；点击临时将WDA空闲/动画等待设为0，完成后恢复原设置。

返回 steps、results、transitions、status、total_ms；事件带step编号，衔接事件为transition/transition_completed。单步`click(target)`继续可用。Demo保留网页入口和布局，后台调用同一run，去掉逐步结束后的额外结果截图；日志和编号图由事件展示。

## 安装与第一次调用

以下命令从项目根目录执行，Python 3.10+：

```sh
python3 -m venv .venv
.venv/bin/pip install -e '.[android]'
```

按平台选择 `.[android]`、`.[harmony]`；iOS 仅需要 `pip install -e .`。需要同时连接三端时使用 `pip install -e '.[android,harmony]'`。网页另选 `.[demo]`，外部组件不需要 FastAPI、scrcpy、ffmpeg 或数据库。

```python
from getpass import getpass
from jev_phone import AndroidClicker

with AndroidClicker('ADB_SERIAL', getpass('OpenRouter Key: '), provider='openrouter') as phone:
    result = phone.click('点击当前画面上的设置')
    print(result['selected'], result['point'], result['timings'])
```

三端的构造入口：

```python
AndroidClicker(serial, api_key, provider='openrouter')
IOSClicker(wda_url, api_key, provider='openrouter', session_id=None)
HarmonyClicker(serial, api_key, provider='openrouter')
```

外部 Planner、脚本、工具调用或缓存负责产生当前目标。每次 `.click()` 只接收一句明确的点击目标。它采集当前树与截图、生成编号候选、请求有限选择、执行候选中心点击，返回结果；不规划完整任务，不提供输入、滚动、断言、应用启动或设备调度。

## 无网页的可运行示例

先打开要操作的应用，确保目标在屏幕上。示例从环境变量读取对应 Key；未设置时用隐藏终端输入，不将 Key 写入代码、配置或结果：

```sh
.venv/bin/python examples/click.py android ADB_SERIAL '点击设置'
.venv/bin/python examples/click.py ios http://127.0.0.1:18100 '点击通用'
.venv/bin/python examples/click.py harmony HDC_SERIAL '点击显示和亮度'
```

OpenAI 官方通道加 `--provider openai`。默认环境变量为 `OPENROUTER_API_KEY`，官方为 `OPENAI_API_KEY`。两种通道的模型与协议不同，Key 不可混用；实际请求可能产生费用。

`--evidence .data/my-run` 保存当帧、编号图、点击返回和立即后截图。`after.image` 保留平台原始图片格式，支持识别图片内容的查看器可直接打开；后截图不自动表示页面稳定。

## 不同设备并行，同设备顺序

编辑 `examples/devices.json` 为实际设备、WDA 地址与每台设备的目标序列，再运行：

```sh
.venv/bin/python examples/parallel.py examples/devices.json
```

一个设备一个 job，不同 job 用线程并行；每个 job 内按 targets 顺序执行。一台失败会停止该台后续步骤，其他设备继续，最终退出码为 1。每步重新采集，候选、截图、结果各自独立。组件内以 adapter identity 的锁保证同进程中同身份实例串行；这不是跨进程设备锁。同一个 iOS 设备用不同 WDA 别名连接可能绕过身份锁，调用方须统一 URL；不同进程操作同台设备须自行协调。

## 结果、事件与失败

`result` 包括 platform、device、target、selected、bounds、point、timings、total_ms、non_model_ms、model 和 status。point 始终是截图像素坐标；iOS 平台层转换为 WDA point。status=`driver_completed` 只表示驱动点击返回，不代表目标页面或业务成功。

`on_event` 同步接收 observe、candidates、selected、completed；candidates 有 image_bytes、before_bytes。回调不要抛异常，耗时回调会计入链路墙钟时间。每次调用模型仅包含当前目标、固定说明与新候选/截图，无历史步骤。

NOT_FOUND、UNCERTAIN、无候选、视口变化会停止点击；模型 HTTP、设备连接、解析错误可能分别抛 RuntimeError/httpx 等异常，外部系统应捕获 Exception 并按自己的策略处理。组件不自动救援或重用旧坐标，不应对不明确是否已执行的设备超时盲目重试。close/context manager 释放模型连接；借用 iOS session 不删除，自己创建的 session 会删除。WDA 清理失败目前可能抛异常，应结合已返回证据判断实际动作状态。

安卓/鸿蒙沿用V3通道，每次采集一次尺寸、截图和树，模型返回后不新增设备查询或等待；iOS仍保留原有采集方式，等待单独优化。跨步骤的页面稳定与业务断言由调用方确认。结果截图、层级含个人信息，作为本地产物保存，不进入分发包。
