# 三端设备准备与排错

组件连接使用者准备好的设备服务；不管理模拟器、设备池、签名、应用安装和账号。真机与模拟器共用平台适配，但各组合的验证状态单列，见验证报告。

## Android：ADB + UiAutomator2

安装 Android SDK Platform Tools，将 adb 加入 PATH。真机打开开发者选项和 USB 调试，插入电脑、接受 RSA 授权；模拟器由 Android Studio Device Manager 启动。`adb devices -l` 必须显示 `device`，使用其第一列作为 serial。offline 检查设备连接，unauthorized 在手机接受授权，多设备必须指定 serial。

```sh
.venv/bin/pip install -e '.[android]'
adb devices -l
.venv/bin/python examples/click.py android ADB_SERIAL '点击设置'
```

首次连接 UiAutomator2 会准备设备端服务，需要设备允许安装/调试。截图与点击都使用 UiAutomator2；SDK 调用不需要 scrcpy。屏幕要解锁，目标在当前页可见。树无候选时先检查应用是否暴露可用层级。截图尺寸与视口不符会拒绝点击；不要用旧截图坐标补救。

上游：[UiAutomator2 安装与设备连接](https://github.com/openatx/uiautomator2)。

## iOS：已有 WDA HTTP 服务

使用 macOS 与 Xcode，准备兼容当前 iOS/Xcode 的 WebDriverAgent。模拟器不需要真机签名；真机需配开发团队、Runner 的唯一 bundle ID、设备信任与 Developer Mode，并先在 Xcode 成功运行 WebDriverAgentRunner 测试。完整签名配置按 [Appium XCUITest 真机配置](https://appium.github.io/appium-xcuitest-driver/latest/getting-started/device-setup/) 执行。

模拟器的 WDA 可在本机 HTTP 端口提供服务。真机通常通过 USB 转发设备 WDA 端口，例如已安装 libimobiledevice 后：

```sh
iproxy 18100 8100 -u IOS_UDID
curl --max-time 5 http://127.0.0.1:18100/status
.venv/bin/pip install -e .
.venv/bin/python examples/click.py ios http://127.0.0.1:18100 '点击通用'
```

自行管理 WDA 可按 [上游启动说明](https://appium.github.io/appium-xcuitest-driver/latest/guides/wda-custom-server/) 选择 Xcode 测试或预构建 Runner；预构建产物必须匹配 Xcode/SDK/架构。模拟器可执行 `xcodebuild test-without-building -xctestrun /path/to/Runner.xctestrun -destination 'platform=iOS Simulator,id=SIMULATOR_UDID'`；xctestrun 是你自己构建出的文件，组件不提供它。

18100 是本机示例端口，8100 是常见设备端口；必须与实际 WDA 配置一致。WDA 已有会话可传 session_id，由调用方维护会话生命周期，否则组件创建/删除自己的会话。

候选使用截图 pixel，WDA 接收逻辑 point；适配按当前截图/窗口比例转换，不硬编码 2x/3x，方向比例不符会拒绝。`/status` 超时先排查 WDA 测试进程、模拟器/USB 转发；HTTP 能通还需确认 session/source/screenshot/tap 可用。用 `lsof -nP -iTCP:PORT -sTCP:LISTEN` 确认端口属于WDA；本机127.0.0.1绑定服务可与通配监听冲突，若返回异常内容或连接被重置，使用WDA日志公布的实际地址或配置独立端口，避免访问到其他项目的Agent。点击超时先看设备最终页面，禁止直接重复 tap。取树/按需截图各一次，不增加重复采集；点击临时调整并恢复WDA等待设置。步骤衔接按当前V3参数额外间隔200ms，复用最后一帧。不同 URL 不应指向同台设备并发运行。

## HarmonyOS NEXT：HDC + hmdriver2

安装 DevEco Studio 或对应 Command Line Tools。将 SDK 的 openharmony/toolchains（以及安装版本要求的 hms/toolchains）加入 PATH。真机开启开发者选项和 USB 调试并授权；模拟器在 DevEco Studio Device Manager 启动。确认 `hdc list targets` 返回 serial，不要把 Android ADB serial 当作 HDC serial。

```sh
hdc list targets
.venv/bin/pip install -e '.[harmony]'
.venv/bin/python examples/click.py harmony HDC_SERIAL '点击显示和亮度'
```

hmdriver2 会初始化 UITest 服务、设备 agent 和端口转发，首次连接可能调整设备侧测试服务；避免与其他自动化同时控制同设备。使用现有 Driver 时可传 driver=，组件不会主动关闭共享服务。HDC 服务端口/远端地址按实际环境配置，不强制修改全局 HDC_SERVER_PORT。

布局来自 hmdriver2 JSON，转换为统一候选；可点击容器中的图片子区域会单独候选并裁剪到父边界。每轮刷新显示尺寸/旋转缓存，拒绝截图/视口不一致。采用V3 captureLayout直返树及大JSON分包读取，不走dumpLayout文件传回。点击直调UITest，无hmdriver2固定600ms等待，不新增争用重试或等待。无设备先修复 HDC 连接；UITest 初始化失败确认系统版本和 hmdriver2 支持范围，不把“有 serial”当作点击可用。

上游：[hmdriver2 快速开始与 HDC 配置](https://github.com/codematrixer/hmdriver2)。
